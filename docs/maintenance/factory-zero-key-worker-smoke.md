# Research: zero-key local factory-worker smoke

**Status:** Research, excluded from `FAR-FACTORY-SELF-EVAL-001`. This is an execution-feasibility tool, not a code-delivery agent, independently verified repair, validated factory controller, or accepted FAR theory. The single candidate-visible task is `FAR-MAINT-002` (issue #648), and the separate evaluator's holdout cases are not accessed by this smoke.

## Rationale and prior evidence

PR #605's hosted pilot executed sixty real Qwen2.5-Coder 1.5B model calls; the prior result was 11/30 control repairs and 10/30 treatment repairs, **no observed treatment advantage**. Its pinned `scripts/workflow_efficacy_start_ollama.sh` and `tools/workflow_efficacy_free_agent.py::local_model_digest` already supply a credential-free Ollama model and identity check. Reuse both rather than introducing an API-key provider or a competing model transport. This code changes no existing worker, queue, scientific protocol, or protected GitHub gate.

## What this smoke does

The single-purpose manifest at `research/factory-evaluation/zero-key-worker-smoke-648-v1.json` fixes an existing Git baseline SHA, Git blob of one allowlisted Python source file, the public issue objective, public test module, and a task ID. The smoke validates it with an unambiguous JSON parser, checks that the exact Git base is an ancestor of the inspected checkout, and creates a throwaway detached worktree. Before the model call it runs the public test module in an unprivileged, no-network, read-only Docker container with process, CPU, memory, wall-time, and captured-output bounds.

It then performs **exactly one** request to pinned local Qwen through localhost Ollama. The model sees the candidate-visible task text and the complete one-file source. It may return exactly one JSON object containing a unified Git diff that changes **only that file**. Unexpected paths, extra object keys, duplicate JSON keys, nonfinite tokens, binary or mode changes, invalid diffs, symlink targets, and oversize output fail closed. A valid patch is applied as data in the throwaway worktree. Public tests then run *inside the same bounded Docker environment*. No code generated by the model is executed on the Actions host, no GitHub token is passed to the worker, no branch is pushed, and no PR is created or merged by the smoke.

The runner preserves model response and extracted content, candidate patch, before/after output streams and SHA-256s, model digest and token counts, source identity and a JSON receipt. It removes the throwaway worktree before finalizing the receipt; all failure results remain. Any postpatch pass means **visible tests passed only** and is neither an independent holdout verdict nor a protected delivery. A model-generated patch that is rejected, a failed visible test, a timeout, or a missing model is preserved and is **not** an improvement claim. Output artifacts have GitHub Actions' finite retention; copy and independently verify if preservation beyond that window is needed.

**Controls not established:** Host-wide isolation from the privileged Docker daemon, complete filesystem/network protection against runner compromise, authenticated independent evaluation, protected checks on a model-generated candidate, equivalence of all test environments, a real factory-stage worker/controller integration, and the registered eight-task randomized trial. Git worktrees by themselves are not security sandboxes. The public-test Docker image may lack tools required by the repository's tests; such outcomes must remain FAIL/UNKNOWN rather than being silently interpreted as repaired behavior. Provider API billed cost is zero for the pinned model, but GitHub Actions compute/download and operator costs are not zero.

## Validation

From the repository root, run:

```bash
python -m unittest tests.test_factory_zero_key_smoke -v
python -m py_compile tools/factory_zero_key_smoke.py
```

The workflow `.github/workflows/factory-zero-key-worker-smoke.yml` runs these tests for changes to the smoke's own files. Its model job is additionally restricted to this repository's named development branch targeting `main`, uses a read-only token and `persist-credentials: false`, and retains artifacts even on failure. A reviewer must verify these conditions, that the host job never executes generated source, and that any task-specific result is properly limited.

The hosted smoke command (after the existing Ollama bootstrap) is:

```bash
python -m tools.factory_zero_key_smoke \
  --repository "$GITHUB_WORKSPACE" \
  --task-file research/factory-evaluation/zero-key-worker-smoke-648-v1.json \
  --output "$RUNNER_TEMP/far-worker-smoke-result"
```

The task is an **excluded pretrial feasibility observation**, not one of the eight registered factory-versus-control assignments. Do not reuse its candidate patch or diagnosis in the registered trial without independently assessing information exposure; do not change the frozen scientific protocol or claim comparative throughput gains from this single smoke.
