**Status: Research / unsealed candidate / NOT RUN.** This stage prepares to close issue #685; it does not alter the frozen registration protocol, authorize or grade any of the 24 scored agent arms, or establish an independent result. ## Reuse and boundary

The original synthetic 30-case corpus in `tools/workflow_efficacy_internal_fixtures.py` supplies candidate source code, task specifications, public tests and separately held-out expected outcomes. A deterministic SHA256 ordering chooses twelve cases, with six preregistered, one-shot transient write interruptions; the rule is checked against the exact Git blob. This is a *candidate* cohort: those tasks were previously executed in a separate Qwen 1.5B scripted-repair comparison, so external independence and novelty are **not** established. The 7B coding model's prior exposure must also be independently assessed. Source/oracle digests are computed on the trusted host; only original buggy source, specification and public tests may be exposed to the model. No scorer, hidden expected value or task replacement is shown to an agent.

The candidate runner in `tools/replanning_study_runner.py` reuses the current `orchestrate()` for the control and `run_replanning()` for the treatment. Both invoke the same real model with the same fixed prompt, tools, permissions, time/token/tool budgets and task goal. The treatment can call the same worker again after a host-logged transient fault. The observer binds to the current orchestration result hash and the actual in-memory tool receipt; a separate model planning call can propose an intent. Inputs are not network-capable agent commands: the only exposed tools are bounded in-memory `list_files`, `read_file`, `write_file` to `solution.py`, and `finish`. An untrusted candidate's code is executed **only** by the existing network-disabled pinned Docker grader; expected outputs never enter the worker's messages.

This remains a **candidate, not a certified runner**. Its `CallableRuntime` reports logical VFS separation with `isolation_verified=False` because it is not an independent OS-level isolated agent. The actual provider response and VFS action receipts are recorded with hashes; the observer declaration is not an authenticated signature and a model's `finish` or the coordinator's report is not oracle success. A real study must prove whole-arm tool, token and wall-clock ceilings, inspect raw capture after unexpected termination, independently verify grader and provider receipts and ensure full container isolation. The current code records results as `DIAGNOSTIC_ONLY_NOT_INDEPENDENTLY_ATTESTED` and does not publish scored outcomes.

## What can execute now

`python -m tools.replanning_study_gate` audits 12 deterministic candidate identities, six interruptions, source Git blob and computed source/oracle hashes, and returns `CANDIDATE_NOT_FROZEN`. It rejects a candidate that marks itself sealed or claims results. `python -m tools.replanning_study_runner run-slot` **fails closed** before any model request without an independently sealed separate execution manifest. `python -m tools.replanning_study_runner provider-preflight` interrogates the live local Ollama registry, checking exact 7B model digest. No experiment task is submitted.

An opt-in branch-only GitHub Actions workflow runs the synthetic tests and the provider probe when the commit has the marker `[FAR-REPLAN-PROBE]`. It borrows the existing SHA-pinned Ollama launcher and has read-only repository permissions and no secrets. The workflow result is a time-scoped preflight receipt, **not** a scored task or future provider guarantee. When a separate commit marker `[FAR-REPLAN-SMOKE]` accompanies the probe marker, it also runs both controller arms on noncohort **FWE-001** using a genuine pinned 7B model and the Docker grader. This input is explicitly outside the selected 12 and must never join its denominator. All raw smoke records are uploaded regardless of model success. The smoke exercises mechanics only, not independent oracle authority or FAR superiority.
