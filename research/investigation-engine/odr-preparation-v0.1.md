# Source-bound Open Deep Research preparation

Status: Research. Identity **FAR-ODR-PREP-001**. This is engineering preparation,
with deterministic model and source fixtures. It supplies no competitor score,
live-model effectiveness, human outcome or superiority claim.

The original registered Open Deep Research condition remains **BLOCKED_GOVERNANCE**:
its uncommitted adapter was lost, and its exact historical source cannot be
recovered from the registered profile. This preparation is separately identified
and does not replace that condition or the original agent **0/8** campaign.

The missing integration was an executable bridge to the actual upstream graph.
The [small adapter](../../tools/far_investigation_odr_preparation.py) imports
[Open Deep Research at commit 1b7d2e80db9faa586165c60e09096dbbfd483a64](https://github.com/langchain-ai/open_deep_research/tree/1b7d2e80db9faa586165c60e09096dbbfd483a64),
checks the Git blob identity of all five imported upstream program files, and
invokes its existing compiled graph. No upstream graph source is rewritten.
Its read and search tools call the existing FAR runtime, retaining operator
allowlists, budgets, source receipts, rejections and event journals. There is no
new research engine or memory subsystem.

Only an explicitly typed scripted fixture can be supplied as the model. The
native graph executes its briefing, supervisor, researcher, tool, compression and
report stages. Scoped bindings restore the native model/tool providers after
success or failure, and overlapping adapter sessions fail closed. Live dispatch
is unavailable in this preparation. A future efficacy comparison requires a
separate prospective source/task/model/budget/configuration lock, including the
choice of exposed native tools and common substantive adjudication criteria.
The read-tool subset here is not claimed to represent the full upstream product.

The [retained observation](odr-preparation-observation-v0.1.json) records the actual
native graph return, seven fixture model calls and one journaled fixture source
read, with zero live model calls. It includes source, adapter, fixture, recipe and
dependency identities. Token and billing values are unknown rather than invented.
The [optional dependency lock](requirements-odr-preparation-v0.1.txt) is isolated
from FAR's ordinary runtime. Seven actual-graph and boundary tests pass: source
mutation, disallowed tools, policy rejection, failed graph restoration, raw call
retention and real read-tool integration are exercised. Socket connections are
forbidden during the successful fixture test and recording.

To reproduce these engineering checks in a separate Python 3.12 environment:

```bash
python -m pip install -r research/investigation-engine/requirements-odr-preparation-v0.1.txt
FAR_ODR_UPSTREAM_DIR=/absolute/path/to/pinned/open_deep_research python -m unittest tests.test_far_investigation_odr_preparation -v
python research/investigation-engine/record-odr-preparation-v0.1.py /absolute/path/to/pinned/open_deep_research --output /tmp/new-odr-preparation.json
```

The recording recipe refuses an existing output path. Fresh observations contain
new timestamps and native message identifiers; byte-identical regenerated traces
are not asserted. The retained artifact remains the original preparation record.
Upstream currently emits API deprecation warnings; they are preserved as an
engineering compatibility limit, not interpreted as a scientific failure.

Independent semantic adjudication of the historical tasks and a matched live
existing-system comparison remain unexecuted. There are no customer observations
or purchasing outcomes in this preparation.
