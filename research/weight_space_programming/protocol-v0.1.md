# FAR-WSP-001 prospective experimental protocol v0.1

**Status: Research / DESIGN ONLY / NOT REGISTERED FOR EXECUTION / 0 EXPERIMENTAL RUNS.** This document states a future testable contract. It is not a frozen run registration or proof of an edit. Any numerical engineering gate below is an explicit, provisional decision rule, not an externally validated reliability threshold.

## Hypotheses and falsifiers

- H1 (repair): on a checkpoint with reproducible looping failures, a separately developed sparse edit improves **held-out successful completion** under the same model, sampling settings and resource budget. Falsified locally if complete paired trials do not beat the strongest nonweight intervention.
- H2 (mechanism): improvements are mediated mainly by removing a measurable loop/truncation behavior. Compare truncation, observed repetition, completion and accuracy conditional on completion; perform targeted intervention removal/reversal and dose/control-region edits. H2 is weakened if completion does not change, an unrelated edit works equally well, or correct answers among previously completed responses change substantially without an explanatory test.
- H3 (utility): any benefit survives safety, instruction-following, nonloop arithmetic/reasoning, tool use and latency/token regression tests, across registered seeds. A quality or safety regression outside the declared bounds rejects promotion even if math improves.
- Null/alternatives: the behavioral change comes from sampling, prompt design, increased budgets, a serialized checkpoint, leakage, grader error, quantization, or selection of favorable trials. A causal attribution requires controls addressing each alternative; model attribution is not established merely by comparing two checkpoints.

## Source evidence and limits

Primary: Rikiya Takehi, Jayden Teoh, Alex Zhang and Omar Khattab, *Sparks of Weight-Space Programming*, MIT CSAIL, November 2, 2026, https://rikiyat.github.io/blog/weight-space-programming/. Authors' best Qwen3.5-0.8B run: 131,072 changed weights (0.016%); MATH-500 7.9% to 48.1%; GSM8K 13.8% to 67.1%; IFEval 21.0% to 62.3%; MATH-500 token-ceiling hits 93.0% to 33.1%. They allowed up to 50 practice forward passes, 32,768 generation tokens and many practice examples. We cannot infer an efficient, generally reliable optimizer from a single cherry-picked successful model/failure setting. Gemma 3 270M did not show a comparable benefit under the authors' tests; their own account differentiates removing a bottleneck from acquiring previously absent ability.

Nearby FAR evidence: PR #605 completed the 30-pair one-shot scripted repair experiment, 11/30 control versus 10/30 FAR-instruction treatment. PR #610 registers a separate simulated multistep tool agent study and retains its own integrity rules. Research on mechanistic claims in PR #601 is independent and must not be promoted through this document.

## Prospective registration, before seeing scored outputs

1. Obtain rights to an unmodified open-weight checkpoint and freeze all weight shard and nonweight hashes, architecture, tokenizer and inference backend versions. Use an experiment-specific copy; production artifacts stay untouched. Freeze the changed-tensor allowlist and a small numerical change budget *before* testing. Record full tree digest and the actual count of modified parameters. If repackaging/quantization changes other weights, this is a new intervention, not a sparse edit.
2. Define the failure by baseline measurements: repeated generations, completion versus truncation, parser/format failures, tool mistakes, wrong arithmetic, invalid inference, unsafe actions and hallucinated evidence. Keep multiple candidate explanations and observable discriminators. An observed loop is not, by itself, proof of a specific neural circuit.
3. Prepare distinct development, eligible practice, and scored held-out splits. Freeze case IDs, family labels, exact inputs, task-oracle source, seeds, max tokens, prompt, temperature, decoding options, inference hardware and order. Do not show held-out oracles or test responses to the editor. Register repeat trials and at least one nonloop negative-control family. No adaptive stopping based on the scored sample.
4. Run **five arms** for each identical registered case/seed: base checkpoint; a carefully tuned low-cost prompt fix; an equal-cost decoding or stopping-budget fix; a sham checkpoint serialization with unchanged numeric weights; and the actual sparse weight edit. The sham arm must have its own recorded file-tree identity. Keep inference compute and effective answer budgets comparable or explicitly measure their differences. Editor time/compute and patch preparation must be included in cost reports.
5. Do not allow the proposing agent or the inference model to write the grader, hidden cases, or trusted host outcome comparisons. Grade answer correctness, output completion, tool history, unauthorized actions and safety consequences in separate host code. Preserve the unedited raw request, response and grade trace under SHA-256; reconcile source/config/checkpoint/suite identities. An invalid or missing result is not a failure score: it blocks an effect estimate until properly adjudicated, with no favorable replacements.
6. Register change-control history: failed proposals, all attempted patches, forward-pass counts, reasons for rejection, full editor trace, selection mechanism and excluded dry runs. Evaluate the first registered candidate on the held-out corpus; do not promote the best of multiple after-the-fact edits as a one-shot success. Log any optional experiments as exploratory follow-ups.

## Finite-corpus analysis and go/no-go

The evidence auditor rejects incomplete or substituted five-arm factorial samples. Report actual slot count and identities, paired successes, success conditional on completion, loop/truncation frequency, unsafe-action incidence, per-family effects, tokens, model-serving latency, editing cost, changed parameter fraction and reproducibility of outputs. No binomial independent-sample inference follows from related task variants/seeds. Publish all outcomes, including the negative controls.

An internal *screen* requires that the weight arm exceeds **every** nonweight and sham comparator on successful completion on the complete held-out cohort, never underperforms the strongest nonweight arm within any registered family and has no more unsafe actions than any comparator. This is a strictly necessary screening condition, not a sufficient basis for promotion. The research reviewer must separately assess prospective tolerances for token/latency/energy/cost and shifts in calibration, factuality, instruction following, and safety. A proposed weight edit failing any preregistered safety or cost requirement does not advance. No generic numerical tolerance is silently inferred from the MIT report.

An accepted mechanism claim additionally needs reversible/ablative controls, independent blinded grading, replay from the original checkpoint with the same intervention, and a replication on a second appropriately chosen model/failure family. A general agent-reliability claim needs representative multi-step agent tasks, repeated-run success under a named distribution, runtime authorization and regression tests, and external validation. A commercial value claim needs independently measured customer outcomes. None follows from this experimental framework.

## Evidence-manifest schema (mechanically enforced subset)

The planned `far-wsp/v0.1` manifest has `status: Research`; `checkpoint` contains `base_sha256`, `sham_sha256` and `edited_sha256`; `suite_sha256` and `source_sha256` bind frozen execution material; `arms` is exactly `["base", "prompt_fix", "decode_fix", "sham_edit", "weight_edit"]`; and `slots` contains uniquely keyed `{case_id, seed, family}`. Each of the five observations per slot contains `case_id`, `seed`, `arm`, `checkpoint_sha256`, `trace_path`, `trace_sha256`, `grade_path`, `grade_sha256`. The referenced grade JSON must contain only `correct`, `completed`, `unsafe_action` (booleans), `output_tokens`, `elapsed_ms` (nonnegative integers), and `failure_category` (one of the source's declared finite values). Analysis reads and verifies the supplied bytes, recomputes finite sample rates, and fails closed for missing, duplicated or substituted slots.

**Assurance boundary:** this checker does not independently reconstruct the task oracle, verify that an external model genuinely produced the trace, verify that checkpoint digests were pinned before execution, or prove grade correctness. A mutable manifest with matching digests could be manufactured after the fact. Independent execution provenance, actual oracle replay, checkpoint mapping, and frozen registration must be supplied by a separate trusted runner and review. Synthetic fixtures in the unit suite are never counted as real experimental outcomes.
