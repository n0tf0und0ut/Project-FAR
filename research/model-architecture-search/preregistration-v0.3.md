# FAR-MAS-EXTERNAL-003 — prospective externally sourced data and MAC-proxy comparisons

Status: **Research / prospective freeze / NOT EXECUTED at protocol publication**.

## Why this is needed

The v0.1 search compared unequal model sizes; preregistered v0.2 found no stable depth advantage across synthetic authored binary tasks. The direct next falsifier is whether the machinery can generalize to externally collected, independently named, fixed tasks with stronger, realistic references and explicit compute proxies. No further sweep of the same artificial bit tasks is justified.

## Source authority and explicit limitation

Official DeepMind [CLRS-30](https://github.com/google-deepmind/clrs) and [NAS-Bench-360](https://github.com/rtu715/NAS-Bench-360) datasets and reference environments are **not available** in this execution runtime; network acquisition of official datasets failed. Do not call this a CLRS or NAS-Bench-360 run, or claim their scores or official replication. The available non-authored datasets are the *bundled scikit-learn copies* of the UCI optical-recognition handwritten digits subset (1,797, 64 input features, ten classes) and UCI Wisconsin Diagnostic breast-cancer measurements (569, 30 features, two classes). Their collection is external, but the FAR split, normalization, architecture choice and scoring are **project-authored**, not external blinded evaluation. The UCI digits copy is explicitly a subset of the original UCI test cohort and has no fresh-person held-out population. The Wisconsin classification labels are not evidence of clinical diagnostic validity or suitability.

Controlling versioned experiment source: `tools/model_architecture_external.py` SHA-256 `83cd655603557bd62b95119216aaf674938c698f915eff65fab7f1bd5523202f`; protocol: `protocol-v0.3.json` SHA-256 `73281ff83c57a7893220b21245e45c43a57ecca2089bfd03d2bb391188abf05b`. The protocol stores immutable hashes of both raw dataset arrays and index splits. Code and contract must be committed to GitHub before the first scored run. The source identity binds all result records; any fix after exposure must be a separate, versioned post-execution verifier, not a rewrite of the original scored runner.

## Frozen protocol

1. Datasets, split indices and labels are frozen by `split_seed=20261103`, stratified once into 60% train, 20% validation and 20% test. `StandardScaler` is fit on training examples only. Fixed data hashes and split hashes are checked before model training. Digits are arranged as eight ordered 8-value row tokens; Wisconsin tabular features become 30 ordered scalar tokens. These representation conventions are not model-neutral and must be disclosed.
2. Four known operator families only: **two attention blocks**, **one wide attention block**, **one GRU**, and **one depthwise convolution**. There is no generated novel operator, LLM architecture planner, or open-ended research agent. Each shares input projection, positional parameters, normalization, mean-pooling classification head, residual blocks and two-layer channel FFNs. All inputs are observable in all positions (noncausal attention; GRU has fixed scan order; convolution kernel=3). Only two-block attention has doubled depth.
3. Two larger-than-v0.2 scales: base widths 48 and 72; two budgets 80 and 160 AdamW parameter-update steps; seeds 521, 522 and 523, with fresh optimizer/model state each time. Single-thread CPU execution and common batch size 64, LR 0.004. **96 scored neural runs**, with no outcome replacement. Any failure is preserved.
4. Controls have their width selected by minimizing the worse of relative parameter difference and forward-MAC estimate difference to the two-attention reference, with deterministic tie break. Under the preregistered data/token lengths and scales, every arm must be within **11%** on both. The MAC definition counts dense matrix multiplies, attention products, recurrent-gate matrix multiplies and depthwise convolution; it omits layer norm, nonlinearities, and overhead. Thus it is a **proxy**, not instrumented FLOPs or actual equal CPU/GPU compute. Record individual model size, estimated MACs and actual elapsed training time, not a falsely precise compute equivalence claim.
5. Additional stronger **unmatched reference models**: logistic regression (`lbfgs`, C=1, max_iter=2000), RBF-SVM (C=1, gamma=scale), and 5-NN. All trained on the same train data and evaluated on the same validation/test samples; no hyperparameter tuning based on outcomes. These do *not* meet the neural parameter/MAC bounds, and must not be misrepresented as compute-equated.
6. Primary metric is **held-out accuracy**, with class-level recall recorded to expose the imbalance. For each dataset / width / budget, lock the family selection by **mean validation accuracy across three seeds**, break ties by estimated forward MACs then name. Write a durable `selection_locked` journal event before calling the held-out test for any model in that group. Report test accuracy of the selected family, the best post-hoc test family as a *diagnostic*, and selection regret. The latter is not an alternate winner.
7. Primary preregistered engineering screen at width 72 and 160 steps: the validation-selected neural family's mean test accuracy must exceed the **validation-selected simple reference model's held-out accuracy** by at least +2 percentage points on **both datasets**, with the selected neural family no more than 2 points below the best post-hoc neural family's test accuracy. This is an exploratory **screen**, not a significance test, an independently verified improvement or a reason to claim novelty. No secondary condition can rescue failure.
8. Report each prediction, class count, accuracy, source/dataset/split fingerprints, model-state fingerprint, seed, elapsed time, and actual start/complete sequence. Fail closed on missing runs, mismatched raw data, substituted metrics, duplicate keys, altered journal or changed protocol. Keep all failures and initial preflights. Reproducibility means same-environment source/data reconstruction; it does not imply an external independent audit.

## Acceptance, failure and evidence limits

A successful code run proves that a defined finite experiment ran; positive outcomes do not prove architecture originality, broad domain independence, large-model scalability or an agent able to invent a successor to the Transformer. To promote architectural advantage requires independent held-out tasks and administrators, modern baseline implementations and fair actual FLOP/latency/training-budget accounting at meaningful scale. A negative result is preserved with identical standing.

This is a new experimental Research artifact; neither v0.1 nor v0.2 frozen data/code will be overwritten. No model is used in production FAR inference. No protected-main merge, code review, source-adjudication independence or security gate may be bypassed.
